- 2026-11-01 — Commit SHA must be a full 40-char lowercase hex — short SHAs can become ambiguous, breaking the cache key — active

- 2026-11-01 — Git hardening: user/system git config ignored, only https protocol allowed, `core.symlinks=false`, hooksPath=/dev/null, no submodules, LFS smudge skipped, no terminal prompts, timeout on every git call — repo is untrusted input; symlinks become plain text files so nothing can point outside the clone — active
- 2026-11-01 — Limits: 20,000 files, 200 MB total, 1 MB per file, 120 s per git call — arbitrary, never measured (repo sizes in PROJECT_NOTES.md) — active
- 2026-11-01 — Over-size single files are skipped and counted, not fatal; file-count and total-size overruns are fatal — one big binary shouldn't block analysis of a normal repo — active
- 2026-11-01 — Network test (real GitHub fetch) is marked `network` and skipped by default (`pytest -m network` to run) — keeps CI offline and deterministic — active
- 2026-11-01 — Library and built-in calls (JDK such as `String.trim`, framework such as Spring Data `save`) are noted as library calls, never traced into — owner: only user-defined code (classes, interfaces, abstractions) is ours to explain; built-ins are mentioned, not explained — active
- 2026-11-01 — Answer key for Phase 1 written by hand in `tests/fixtures/spring-petclinic/expected.json` before the tool could extract endpoints/entities — the brief requires expected results before tool output, so the key can't be bent to fit the tool — active
- 2026-11-01 — Java fact IDs are readable and stable: `java:class:<fqn>`, `java:method:<class>#<name>(<param types>)`, `java:field:<class>#<name>` — overloads stay distinct; IDs survive re-runs, which view specs and caching need — active
- 2026-11-01 — If two files declare the same qualified name (e.g. two modules), the second ID gets `@<file>` appended — keeps both facts instead of crashing on a duplicate key; none seen in either petclinic repo — active
- 2026-11-01 — Files with syntax errors are still extracted and listed as "facts may be partial" — Tree-sitter recovers from errors; hiding the file would lose facts, hiding the warning would overclaim — active
- 2026-11-01 — Enum constants and record components stored as fields (flagged `enum_constant` / `record_component`) — Phase 5 switch branches need enum constants; record components behave as fields — active
- 2026-11-01 — `rib facts` caches by repo + SHA: resolve SHA first, skip clone and parse if the snapshot already has facts; nodes and edges are written in one transaction — a half-written snapshot would otherwise look cached — superseded 2026-11-10: always re-extract (owner's choice)
- 2026-11-01 — Pin `tree-sitter>=0.25.2,<0.26` — 0.26.0 segfaults on spring-petclinic test classes (details in PROJECT_NOTES.md) — active, retry when a newer release is out
- 2026-11-01 — Call resolution runs as a second pass over the whole repo: call sites and local variable types are recorded at parse time, resolved after all files are parsed — a call's target is often in another file — active
- 2026-11-01 — Call confidence rules: `exact` = receiver type known (declared type, `this`, implicit call, static call) and exactly one method matches name + argument count, in the class or its repo supertypes; `likely` = several overloads with the same argument count (edge to each), type matched by simple name only, or a Spring Data/library-inherited method; `guess` = receiver type unknown but only one method in the repo has that name + argument count — tree-sitter has no types, so argument types can't pick an overload — active
- 2026-11-01 — Library calls stored as method attribute `library_calls` (e.g. `String.trim`, `OwnerRepository.save (inherited from JpaRepository)`), never as edges; unresolvable calls stored as `unresolved_calls` — owner: only user-defined code is traced; built-ins are mentioned, not explained; gaps must be visible — active
- 2026-11-01 — A call to a library-inherited method on your own type (e.g. `owners.save()` on `OwnerRepository extends JpaRepository`) gets a `calls` edge to your class node, `likely`, plus a library label — keeps the dependency on your repository visible without inventing a method node — active
- 2026-11-01 — Ambiguous overloads whose candidates all return the same type keep that type for chained calls, at `likely` — e.g. `owner.getPet(x).addVisit()`; otherwise the chain stops and the next call is guessed or unresolved — active
- 2026-11-01 — Spring injection: in a class with a Spring stereotype (`@Component`, `@Service`, `@Repository`, `@Controller`, `@RestController`, `@Configuration`, advice), the `@Autowired` constructor or the only constructor → `exact`; `@Autowired`/`@Inject`/`@Resource` fields anywhere → `exact`; Lombok `@RequiredArgsConstructor`/`@AllArgsConstructor` with no visible constructor → fields, `likely` — follows Spring's rules; Lombok's constructor isn't in the source, so it is inferred — active
- 2026-11-01 — Edge kinds so far: contains, calls, extends, implements, overrides, injects; still free text — make it an enum in Phase 1 step 4 once endpoint/entity edges exist — superseded 2026-11-04 by `EdgeKind`
- 2026-11-02 — Endpoints: only classes annotated `@Controller`/`@RestController`; one endpoint node per HTTP verb × class prefix × method path; `@RequestMapping` without `method` → verb `ANY`; paths normalised (leading `/`, no duplicate or trailing `/`); endpoint ID `java:endpoint:<VERB> <path>`, with `@<handler>` appended if two handlers share it — matches Spring's own mapping rules for the common cases; IDs stay readable — active
- 2026-11-02 — Annotation arguments stored as raw source text per element (`annotation_args`), string literals keep their quotes — lets later steps tell a literal path from a constant without losing information — active
- 2026-11-02 — Path built from a constant we can't evaluate (e.g. `@GetMapping(Paths.ITEM)`) keeps the raw expression as `<Paths.ITEM>`, `path_resolved: false`, and its `handles` edge is `guess` — visible but not trusted, per "honesty about what it can't see" — active
- 2026-11-02 — Endpoint inputs: annotated params by annotation (`@PathVariable` path, `@RequestParam` query, `@RequestBody` body, `@RequestHeader` header, `@CookieValue` cookie, `@ModelAttribute` form); unannotated simple types → query and complex types → form, both flagged `implicit` (Spring's default binding); framework-supplied params (Model, BindingResult, RedirectAttributes, HttpServletRequest, …) are not inputs — the Level 3 parameter table needs what the caller sends, not what Spring injects — active
- 2026-11-02 — Response kind: `body` for `@RestController`, `@ResponseBody`, `ResponseEntity`, `Mono`/`Flux`; otherwise `view` (MVC template) — distinguishes JSON APIs from server-rendered pages — active
- 2026-11-04 — Edge kind is now an enum (`EdgeKind`: contains, calls, extends, implements, overrides, injects, handles, maps, relates, stores), checked in Python and by a SQL CHECK constraint — reverses the 2026-11-01 "free text for now" decision, as planned once the Phase 1 edge set was known — active
- 2026-11-04 — JPA data model: one `entity` node per `@Entity` class (`java:entity:<fqn>`, name = table), linked by `maps` class → entity; `@MappedSuperclass` / `@Embeddable` are a `jpa` attribute on the class, not nodes — only entities have tables; superclasses already have `extends` edges — active
- 2026-11-04 — Table name: `@Table(name)`, else `@Entity(name)`, else the class name, recorded with `table_source` (`@Table` / `@Entity(name)` / `default`) — this is JPA's logical name; Spring Boot's naming strategy may change the physical name (e.g. `PetType` → `pet_type`), so `default` names are flagged rather than converted — active
- 2026-11-04 — Relations: a field with `@OneToOne`/`@OneToMany`/`@ManyToOne`/`@ManyToMany` gets attribute `relation: {kind, target}` and a `relates` edge field → target entity; target = `targetEntity`, else the collection's element type (`Map` → value type), else the field type — the field is the evidence (file, line, `mappedBy`/`cascade` in `annotation_args`) — active
- 2026-11-04 — JPA annotations are trusted by their import: `jakarta.persistence` / `javax.persistence` (explicit, wildcard or fully qualified) → `exact`; no matching import → `likely`; imported from another package (e.g. Morphia's `@Entity`) → ignored — same simple names are used by non-JPA libraries — active
- 2026-11-04 — Repositories: an interface extending a Spring Data base (`Repository`, `CrudRepository`, `ListCrudRepository`, `PagingAndSortingRepository`, `ListPagingAndSortingRepository`, `JpaRepository`) imported from `org.springframework.data` gets attribute `repository: {base, entity, id}` and a `stores` edge to the entity from the first type argument — Spring Data's own rule for the domain type — active
- 2026-11-04 — Lombok: a call to `getX`/`isX` (boolean)/`setX` with no declared method, where the class (or a repo superclass) has `@Data`/`@Value`/`@Getter` (`@Data`/`@Setter` for setters) or the field has `@Getter`/`@Setter`, gets a `calls` edge to the class (`likely`) and a `library_calls` label "generated by Lombok @X"; the getter returns the field's type for chained calls — brief Phase 1 step 5: mark generated code instead of leaving it unresolved or guessing — active
- 2026-11-04 — Phase 2 plan approved by the owner (4 steps, see STATUS.md) — active

Alternative `spring-projects/spring-data-examples` rejected: a sample collection, 6,692 Java files — active
- 2026-11-04 — New dependencies approved for Phase 2: PyYAML (6.0.3, `safe_load` only) and defusedxml (0.7.1; old but still the standard safe XML parser) — repo files are untrusted: YAML must not build objects, XML must not expand entity bombs — active, added in Phase 2 step 1
- 2026-11-10 — `rib facts` always re-extracts and replaces that commit's facts (`FactStore.replace_facts`, one transaction); no skip-if-cached for code facts. Caching is kept for LLM output only (Phase 3), keyed by commit + prompt + model — owner chose this over versioning the cache: extraction takes 0.7–2.2 s on the test repos, and a cache keyed by commit served stale facts after every extractor change. Supersedes the 2026-11-01 "`rib facts` caches by repo + SHA" decision and the open cache-versioning question — active
- 2026-11-10 — Build/deploy facts: one `module` node per directory with a build file (`build:module:<dir>`; Maven and Gradle in one dir = one module listing both tools, Maven read first); Dockerfiles, Compose services, Kubernetes objects and Spring config files are `config` nodes with a `config_type`. `service` nodes are not created yet: deciding what is a service is classification (step 2) — a Compose entry can be a database, and a Maven module can be a library — active
- 2026-11-10 — Module links: `contains` (aggregator → `<module>` / Gradle `include`), `extends` (`<parent>` that is a repo module), `depends_on` (non-test dependency on a repo module, Gradle `project(':x')`, Compose `depends_on`). Maven edges are `exact`; Gradle edges are `likely` because build scripts are code we match as text and never run — active
- 2026-11-10 — Spring config stored as flat keys (`spring.datasource.url`) with value and line, one entry per YAML document / `#---` section, with the document's profile; values of keys that look secret (password, secret, token, credential, api-key, private-key) are replaced by `<redacted>` unless they are a `${...}` placeholder; Kubernetes Secrets keep only kind and name; Compose environment values are redacted the same way — facts go to an LLM in Phase 3 and are shown in the UI, so secrets from repos never enter the store — active
- 2026-11-10 — Untrusted file formats: XML through defusedxml (DTDs/entities refused → file listed as a parse error); YAML through `yaml.compose_all` with SafeLoader, never constructing objects, with a 20,000-node budget per file against alias bombs (arbitrary — never measured); Helm templates (`templates/` + `{{`) skipped, not reported as errors — active
- 2026-11-10 — Spring Boot "is this module an app" is not read from `spring-boot-maven-plugin`: in the microservices repo the plugin sits in the root POM and children inherit it, so the module's own pom says nothing. Step 2 uses `@SpringBootApplication` classes instead — active
- 2026-11-10 — Service = a `@SpringBootApplication` class in main code (files under `src/test/` excluded — petclinic has one in a test), placed in the innermost build module holding its file; name from `spring.application.name` in that module's default config (no profile, first document), else the module name, else the class name (`name_source` records which). `service` facts get a `contains` edge to their module — the main class is the one signal that is always in the source; plugins and Dockerfiles are inherited or optional — active
- 2026-11-10 — Service roles, each stored with the file and line it came from (`role_evidence`): `@EnableEurekaServer` → discovery_server, `@EnableConfigServer` → config_server, `@EnableAdminServer` → admin_server, `@EnableDiscoveryClient`/eureka or consul client dependency → discovery_client, `spring.config.import: configserver:` / `spring.cloud.config.uri` → config_client, `spring.cloud.gateway…routes[n]` in config → gateway. A gateway is recognised by its routes, not its dependency — genai-service in the microservices repo depends on the gateway library but routes nothing — active
- 2026-11-10 — Classification is computed from facts on demand (`system.classify`), not stored — it's cheap and deterministic, and stored verdicts would go stale as rules change — active
- 2026-11-10 — Layout rules: no build file → unclear; more than one root build (not aggregated by another) → monorepo; one root aggregating others → multi-module; else single project. Runtime rules: 0 apps → library (unclear without a build file); 1 app → monolith, or modular monolith in a multi-module build; 2+ apps → microservices only if there is service infrastructure (discovery, config server, gateway routes) and no database shared between apps, otherwise unclear with the conflicting evidence shown — the brief says to say "unclear" when signals conflict; mall (4 apps, one shared MySQL, no infrastructure) is the test case — active
- 2026-11-10 — Shared database = the same `spring.datasource.url` (placeholder defaults filled in, query string dropped) in the non-test configs of two or more services, any profile — dev and prod profiles are both real deployments — active
- 2026-11-10 — `deployed_by`: a Compose service or Kubernetes workload is linked to a service when its name equals the service name, its image name (without registry and tag) equals it, or its Compose `build` folder is the service's module — name matching, so it can miss renamed containers; used as evidence only, not as an edge — active
