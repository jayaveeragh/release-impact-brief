## Trade-offs and known gaps

- 2026-11-26 — Impact gaps: interprocedural data flow is one step (a branch reading a changed call's result in the direct caller, not further up); flows only from the overview (module flows aren't stored); template-rendered output and framework-called code are listed as unseen rather than traced; the size thresholds are untuned; the model's location picks can widen the brief (e.g. picking a stored field turns "small" into "big") — the user can untick them — active
- 2026-11-24 — Chat gaps: keyword retrieval misses questions phrased without any word the code uses (the synonym list is tiny); one question at a time, no follow-up memory; answers are cached by exact question text; the kept clones under `.rib/clones/` are never cleaned up automatically — active
- 2026-11-22 — Raising the fetch limits lets big repos in, but summarising them with the local model takes hours the first time (≈ 9 s per class; a 20,000-file repo may have ~5,000 classes ≈ 12 h — extrapolated, never measured). Facts, structure and branch maps don't use the model and stay fast. Option B (skip summaries for big repos, summarise modules on demand) is the follow-up if this matters. A running `rib serve` keeps the settings it loaded at start: restart it after changing `.env` — active
- 2026-11-17 — Branch-map gaps: loops aren't branch points; lambdas are skipped; local dataflow is flow-insensitive (over-attributes after reassignment); only the handler's own method is analysed — branches inside called services/validators are not (the map lists the calls on each path); `switch` fall-through isn't modelled; custom validators are named, not traced; implicit model attributes (petclinic's `owner` comes from a @ModelAttribute method using the path id) are shown as form inputs. Module flows from the local model include trivial getter/setter steps — active
- 2026-11-16 — Web gaps: jobs are in memory (a server restart forgets running analyses; views survive); one analysis at a time; the JS bundle is ~1.6 MB because ELK is bundled (fine locally; could load it lazily); petclinic's diagram is dominated by its 17 endpoints because the model chose to draw them all; no auth — the server binds 127.0.0.1 only — active
- 2026-11-15 — Local-model gaps: Ollama must be running (`ollama serve`, or `brew services start ollama` to keep it up after reboot); RIB_CONCURRENCY above what Ollama serves in parallel only queues requests; the model sometimes puts free text where a fact reference belongs (removed by the validator) — active
- 2026-11-15 — View spec gaps: one repo-level view only (module views come in Phase 5); for mall the fact table lists 246 endpoints, which the LLM may not need for an overview; the view answer is cached like summaries but its cost isn't recorded in the cache row (None); verdict evidence is file:line text from the classifier, not fact references — active
- 2026-11-14 — Summary gaps: classes in modules without a build file are grouped as "(no build module)"; the later-level cost bound is rough (facts at ~3 chars per token plus longest possible answers); a run with module/repo failures re-asks them next time but class answers already cached are reused; source over 8,000 characters is cut, so very long classes are summarised from their facts plus the start of the code — active
- 2026-11-12 — LLM requests are non-streaming, so max_tokens should stay around 16k or below (larger replies risk HTTP timeouts); Haiku 5.5's higher price above 100K-token prompts isn't modelled; the 1-hour cache TTL isn't used (5-minute default) — fine for summaries sent back to back — active
- 2026-11-11 — Outside-system gaps: config-declared links back into the repo (e.g. `spring.config.import: configserver:` → config server) are not edges yet, only excluded from grey boxes; outside systems reached only from code constants or SDK clients (mall's `MinioClient.builder()` with config values, Alipay SDK) are found through their config keys, not the code; one grey box per key prefix can merge two different systems under one prefix — active
- 2026-11-11 — Connection gaps: URLs built from constants or method calls (only literals, `@Value` placeholders and Feign names are read); client classes in shared library modules (no owning service, skipped); Spring Cloud OpenFeign URLs from config (`spring.cloud.openfeign.client.config`); gateway routes defined in Java (`RouteLocator` beans); message destinations from enums/constants (mall's publisher); cross-service messaging links; data stores configured only through custom keys (mall's `minio.endpoint`) — active
- 2026-11-10 — Classification gaps: microservices without Spring Cloud (plain Kubernetes services calling each other over HTTP) come out "unclear" until step 3 adds service-to-service calls as a signal; config served by an external config repo (microservices uses one on GitHub) is invisible, so those services show no port or datasource; `server.port` only from the default profile (mall-portal's 8085 lives in dev/prod files, so it shows none); non-Spring entry points (`main` without `@SpringBootApplication`, Quarkus, Micronaut) aren't services yet — active
